# Wallet visual coverage audit

This inventory maps production surfaces to distinct evidence obligations. Read the catalogue for exact state IDs, test methods, configurations and renderer applicability; read the test result for what actually executed. The inventory is source coverage, not a claim that all listed host or hardware tests passed. A baseline is expected appearance, while an app-host capture observes a journey.

Compose Android and Compose iOS share `WalletVisualScenarios`; SwiftUI uses production app/shared views through `WalletVisualTests`. Browser account states use their existing separate catalogue and Playwright report. A reusable component's variants plus one representative composed screen usually provide more signal than capturing every screen that embeds it.

## Remaining boundaries and gaps

- Pure mobile snapshots intentionally do not reproduce system camera/biometric/file/credential pickers, browser authorization or permission dialogs. Use selected actual-host/device evidence when a PR affects those boundaries.
- Native credential deletion confirmation and failed-media fallback do not currently have a distinct catalogue capture. Compose deletion semantics and the representative reset dialog cover the shared destructive-action layout; native deletion/system-alert appearance and each renderer's failed-media presentation remain targeted host/visual follow-ups. Do not report them as verified platform parity.
- Native PIN-storage retry affordance differs from Compose. This audit records the production behavior; adding a new native recovery action is a product change requiring its own behavior proof.
- Key recovery and backup confirmations are covered by the native host journey; platform-capability differences require the corresponding host/device proof rather than adding synthetic support to another demo. Protected signing, hardware storage, NFC/BLE and standards conformance remain separate qualification lanes.

Add a state only for a distinct reachable risk. Prefer a targeted compact-plus-large-text case for wrapping/pinned actions over multiplying every screen by every configuration. Each new reference must be recorded deliberately, visually inspected and then compared with recording disabled.
