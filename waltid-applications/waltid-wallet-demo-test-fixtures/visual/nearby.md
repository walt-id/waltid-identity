# Nearby review and outcome contract

Home launches nearby sharing in a focused sheet. Connection options opens the relevant settings within that task and returns to the originating phase. One Prepare sharing control is off for Ask each time and on for preparation; it never grants consent by itself. The control and connection-row geometry remain stable while the SDK replaces the engagement, with temporarily unavailable actions disabled.

Nearby sharing uses the same whole-row credential choices and information-group components as online sharing. One **Information to share** section groups the selected documents and their actual requested values, with a separate Details action opening the full stored-information layout. Required elements have no ineffective checkbox; optional fields retain their request-index/namespace references and explicit retention notices. Nearby sharing keeps the wallet's credential thumbnails and trailing action groups. Request meaning, reader trust, required elements, prepared approval and legal actions remain owned by the existing SDK session. The UI does not reconstruct those decisions.

The Compose and native hosts separate engagement, review, reader details, prerequisites and outcomes into focused components. Stored credential parsing runs off the UI thread and discards stale results. Selection rows represent credential selection, without a misleading details-navigation chevron. Requested field labels and values use the same normalized metadata as credential details; absent data remains explicitly unavailable. Receipts and prepared summaries reuse those labels and thumbnail art, showing only the approved field set. Reader identity and trust labels come from the immutable SDK review.

An accessible header X requests one legal cancellation and waits for teardown before leaving the task. SDK rejection or an unavailable legal action keeps the task visible; receipt Done ends the task without another cancellation. Local Close remains distinct from protocol refusal. Actions stay trailing, on one line when labels fit, and wrap for compact widths or accessibility text. Permission remediation retains its busy state. Receipt and recovery actions stay in a footer while content scrolls. A completed response is described as locally sent; it is not presented as proof that the reader verified or accepted it. Expired prepared sharing requires review and a fresh approval; Try again does not silently recreate consent.

A normal completed response with a local receipt follows the shared five-second idle success return. Interaction or assistive technology keeps the receipt open. Decline, missing/uncertain receipts, errors and recovery never auto-dismiss. No timer acts while the SDK is sending, waiting for another request or terminating the connection.

The deterministic catalogue covers QR readiness, a blocked Bluetooth prerequisite, trusted reader review with retention, prepared-approval expiry and the sent receipt. The compact review is 320×568 with Compose font scale 1.5 / SwiftUI accessibilityMedium; the second viewport shows the field value and retention notice above the pinned actions. The same synthetic request facts are read from `wallet-visual-data.json`. Native tests also decode the QR from the actual wallet chrome at two phone sizes. Semantic and lifecycle suites separately exercise credential/field choices, trust distinctions, permission/settings handling, stale decisions, cancellation, reconnect and prepared approval.

These fixtures do not request OS permissions or transmit credentials over BLE/NFC. Platform provider windows, hardware key prompts, physical-reader interoperability and background radio behavior need their separate live/device lanes. The catalogue records rendered states, not formal conformance.
