# walt.id ktor-authnz: Quickstart

## 1. Configure

```kotlin
fun Application.module() {
    install(KtorAuthnz) {
        accountStore = MyAccountStore // implements EditableAccountStore; InMemoryAccountStore() to start with
    }
    install(Authentication) { ktorAuthnz("ktor-authnz") }
    install(ContentNegotiation) { json() }

    routing {
        route("auth") { authFlows(flows) }
        authenticate("ktor-authnz") {
            get("/me") { call.respond(call.authnzPrincipal()!!.accountId) }
        }
    }
}
```

Errors of ktor-authnz carry their HTTP status (`HttpStatusError`); walt.id services answer them with it. Outside the
services, map them in your `StatusPages`.

## 2. Define flows

```kotlin
val flows = listOf(
    // password only
    AuthFlow.fromConfig("""{"method": "userpass", "expiration": "1d", "success": true}"""),
    // email + password, then TOTP or a recovery code
    AuthFlow.fromConfig(
        """{"method": "email", "continue": [
             {"method": "totp", "success": true},
             {"method": "recovery-code", "success": true}]}"""
    ),
)
```

Two flows cannot start with the same method: the first step decides which flow a login follows.

## 3. Log in

Single step - the session is opened by the first step:

```http
POST /auth/userpass
Content-Type: application/json

{"username": "alice", "password": "123456"}
```

```json
{"session_id": "cf7951d3-...", "status": "SUCCESS", "token": "70d2ac4a-...", "expiration": "2026-10-02T12:00:00Z"}
```

Several steps - follow `next_method`, which names the next URL under the session:

```http
POST /auth/email
{"email": "alice@example.com", "password": "123456"}
```

```json
{"session_id": "caf4d705-...", "status": "CONTINUE_NEXT_FLOW", "next_method": ["totp", "recovery-code"]}
```

```http
POST /auth/caf4d705-.../totp
{"code": "768944"}
```

```json
{"session_id": "caf4d705-...", "status": "SUCCESS", "token": "26755b7d-..."}
```

Multi-step methods (OIDC, VC) answer `CONTINUE_NEXT_STEP` with a `next_step` - e.g. a URL to open - and a
`next_step_description`.

Explicit start (optional): `POST /auth/start?flow=email` opens a session before its first step; then
`POST /auth/{session_id}/email`.

## 4. Use the token

Send it as `Authorization: Bearer <token>` (or the `ktor-authnz-auth` header); browsers get it as an HttpOnly,
SameSite=Strict cookie. To log out, a route of yours calls `getAuthenticatedSession()` and `logout()` on it.

## What a client sees on errors

| Status | Meaning |
|---|---|
| 400 | malformed request, or the session cannot take this step (complete, expects another method) |
| 401 | wrong credential, invalid challenge or token |
| 404 | unknown session, unknown account |
| 429 | too many failed attempts on the session or for the account identifier |
